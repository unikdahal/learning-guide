## 1. The relational model

- **Relation** = table; **tuple** = row; **attribute** = column; **domain** = the set of allowed values of an attribute; **degree** = number of attributes; **cardinality** = number of tuples.
- A relation is a **set**: no duplicate tuples, no row order; values are atomic (1NF).

**Integrity constraints:**
- **Domain** — values from the attribute's domain (type, CHECK).
- **Entity integrity** — the primary key is **unique and not NULL**.
- **Referential integrity** — a foreign key value must match an existing primary key in the referenced table (or be NULL). Actions on delete/update: RESTRICT, **CASCADE**, SET NULL, SET DEFAULT.
- **Key** (UNIQUE), NOT NULL, CHECK, and general **assertions**.

## 2. The sample schema

```sql
Department(dept_id, dname, location)
Employee(eid, name, dept_id, salary, manager_id)   -- dept_id → Department, manager_id → Employee
Project(pid, pname, dept_id)
WorksOn(eid, pid, hours)                           -- M:N between Employee and Project
```

## 3. Relational algebra

| Operator | Symbol | Meaning |
| --- | --- | --- |
| Selection | σ (condition)(R) | rows that satisfy the condition |
| Projection | π (attributes)(R) | chosen columns (duplicates removed) |
| Union, intersection, difference | ∪, ∩, − | set operations on **union-compatible** relations |
| Cartesian product | R × S | every pair of tuples |
| Rename | ρ | rename a relation or attributes |
| **Natural join** | R ⋈ S | product + equality on common attributes, common columns kept once |
| Theta join | R ⋈θ S | product filtered by a condition |
| Outer joins | ⟕ ⟖ ⟗ | keep unmatched tuples, padding with NULL |
| **Division** | R ÷ S | tuples of R related to **all** tuples of S |

Selection, projection, union, difference, product and rename are the **fundamental** operations; the rest can be built from them.

**Examples:**
- Names of employees earning over 50,000: **π name (σ salary > 50000 (Employee))**
- Names of employees in the "Research" department: **π name (σ dname = 'Research' (Employee ⋈ Department))**
- Employees who work on **every** project of department 5: **π eid, pid (WorksOn) ÷ π pid (σ dept_id = 5 (Project))**
- Employees not working on any project: **π eid (Employee) − π eid (WorksOn)**

**Tuple relational calculus** (non-procedural — what, not how): `{ t.name | Employee(t) ∧ t.salary > 50000 }`.

## 4. SQL — DDL

```sql
CREATE TABLE Department (
  dept_id  INT PRIMARY KEY,
  dname    VARCHAR(50) NOT NULL UNIQUE,
  location VARCHAR(50)
);

CREATE TABLE Employee (
  eid        INT PRIMARY KEY,
  name       VARCHAR(60) NOT NULL,
  dept_id    INT,
  salary     DECIMAL(10, 2) CHECK (salary > 0),
  manager_id INT,
  FOREIGN KEY (dept_id) REFERENCES Department(dept_id) ON DELETE SET NULL,
  FOREIGN KEY (manager_id) REFERENCES Employee(eid)
);

ALTER TABLE Employee ADD email VARCHAR(100);
DROP TABLE Project;            -- removes the table and its definition
TRUNCATE TABLE WorksOn;        -- removes all rows, keeps the table
```

## 5. SQL — queries

```sql
-- 1. Employees in Research, highest paid first
SELECT e.name, e.salary
FROM Employee e JOIN Department d ON e.dept_id = d.dept_id
WHERE d.dname = 'Research'
ORDER BY e.salary DESC;

-- 2. Number of employees and average salary per department, only departments with > 5 staff
SELECT d.dname, COUNT(*) AS staff, AVG(e.salary) AS avg_salary
FROM Department d JOIN Employee e ON e.dept_id = d.dept_id
GROUP BY d.dname
HAVING COUNT(*) > 5;

-- 3. Employees earning more than the company average (subquery)
SELECT name FROM Employee
WHERE salary > (SELECT AVG(salary) FROM Employee);

-- 4. Second-highest salary
SELECT MAX(salary) FROM Employee
WHERE salary < (SELECT MAX(salary) FROM Employee);

-- 5. Each employee with their manager's name (self join)
SELECT e.name AS employee, m.name AS manager
FROM Employee e LEFT JOIN Employee m ON e.manager_id = m.eid;

-- 6. Departments with no employees
SELECT dname FROM Department d
WHERE NOT EXISTS (SELECT 1 FROM Employee e WHERE e.dept_id = d.dept_id);

-- 7. Names starting with 'S'; salary in a range; listed departments
SELECT name FROM Employee
WHERE name LIKE 'S%' AND salary BETWEEN 40000 AND 80000 AND dept_id IN (1, 2, 5);

-- 8. Updates and deletes
UPDATE Employee SET salary = salary * 1.10 WHERE dept_id = 3;
DELETE FROM Employee WHERE eid = 101;
INSERT INTO Department VALUES (7, 'IT', 'Kathmandu');
```

**Order of evaluation:** FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. **WHERE filters rows before grouping; HAVING filters groups after.** Aggregates: COUNT, SUM, AVG, MIN, MAX (NULLs ignored except by COUNT(*)).

**Joins:** INNER (matches only), LEFT/RIGHT OUTER (keep all rows of one side), FULL OUTER, CROSS (product), self join, natural join.

## 6. Views, assertions, triggers, authorisation

```sql
-- View: a stored query (virtual table) — security and simplicity
CREATE VIEW ResearchStaff AS
SELECT e.eid, e.name FROM Employee e JOIN Department d ON e.dept_id = d.dept_id
WHERE d.dname = 'Research';

-- Assertion: a database-wide constraint (standard SQL; few DBMSs implement it)
CREATE ASSERTION salary_cap CHECK (NOT EXISTS (SELECT * FROM Employee WHERE salary > 1000000));

-- Trigger: run automatically on an event (event–condition–action)
CREATE TRIGGER log_salary_change
AFTER UPDATE OF salary ON Employee
FOR EACH ROW
WHEN (NEW.salary <> OLD.salary)
  INSERT INTO SalaryAudit(eid, old_salary, new_salary, changed_at)
  VALUES (NEW.eid, OLD.salary, NEW.salary, CURRENT_TIMESTAMP);

-- Authorisation
GRANT SELECT, UPDATE (salary) ON Employee TO hr_clerk;
REVOKE UPDATE ON Employee FROM hr_clerk;
GRANT SELECT ON ResearchStaff TO research_lead WITH GRANT OPTION;
```

Views can be updated only when simple (one base table, no aggregates/DISTINCT/GROUP BY). A **materialised view** stores the result physically and must be refreshed.

## Lok Sewa: write it (10 marks · 16 minutes)

**Question.** For the schema above, write SQL to: (a) create the Employee table with constraints; (b) list each department's name and total salary, highest first; (c) find employees who earn more than their manager; (d) give a 10% raise to employees of the 'IT' department; (e) create a view of employees without a project.

<details>
<summary>Model answer</summary>

```sql
-- (a)
CREATE TABLE Employee (
  eid        INT PRIMARY KEY,
  name       VARCHAR(60) NOT NULL,
  dept_id    INT REFERENCES Department(dept_id),
  salary     DECIMAL(10, 2) CHECK (salary > 0),
  manager_id INT REFERENCES Employee(eid)
);

-- (b)
SELECT d.dname, SUM(e.salary) AS total_salary
FROM Department d JOIN Employee e ON e.dept_id = d.dept_id
GROUP BY d.dname
ORDER BY total_salary DESC;

-- (c)
SELECT e.name
FROM Employee e JOIN Employee m ON e.manager_id = m.eid
WHERE e.salary > m.salary;

-- (d)
UPDATE Employee
SET salary = salary * 1.10
WHERE dept_id = (SELECT dept_id FROM Department WHERE dname = 'IT');

-- (e)
CREATE VIEW NoProject AS
SELECT eid, name FROM Employee
WHERE eid NOT IN (SELECT eid FROM WorksOn);
```

(For (e), NOT EXISTS is safer than NOT IN if WorksOn.eid could be NULL.)
