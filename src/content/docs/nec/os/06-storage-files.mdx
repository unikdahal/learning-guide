## 1. Disks

A hard disk has platters → tracks → **sectors**; tracks at the same position on all surfaces form a **cylinder**.

**Access time = seek time** (move the arm to the cylinder — the biggest part) **+ rotational latency** (wait for the sector; average = half a rotation) **+ transfer time**.

Example: 7200 RPM → one rotation = 60/7200 s = 8.33 ms → average rotational latency **4.17 ms**.

SSDs have no moving parts: no seek or rotation; limited write cycles (wear levelling); the disk-scheduling algorithms below matter mainly for hard disks.

## 2. Disk scheduling

Requests for cylinders **98, 183, 37, 122, 14, 124, 65, 67**; head at **53**; cylinders 0–199.

| Algorithm | Service order | Head movement |
| --- | --- | --- |
| **FCFS** | 53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67 | **640** |
| **SSTF** (shortest seek first) | 53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183 | **236** |
| **SCAN** (elevator), moving towards 0 | 53 → 37 → 14 → **0** → 65 → 67 → 98 → 122 → 124 → 183 | 53 + 183 = **236** |
| **SCAN**, moving towards 199 | 53 → 65 … 183 → **199** → 37 → 14 | 146 + 185 = **331** |
| **C-SCAN**, towards 199 | 53 → 65 … 183 → 199, jump to **0** → 14 → 37 | 146 + 199 + 37 = **382** (counting the return) |
| **LOOK**, towards 199 | 53 → 65 … 183 → 37 → 14 (turn at the last request) | 130 + 169 = **299** |
| **C-LOOK**, towards 199 | 53 → 65 … 183, jump to 14 → 37 | 130 + 169 + 23 = **322** |

- **FCFS** — fair, slow. **SSTF** — like SJF: good average, can **starve** distant requests. **SCAN** — sweeps end to end. **C-SCAN** — sweeps one way, returns without serving: **more uniform wait times**. **LOOK / C-LOOK** — like SCAN/C-SCAN but turn at the last request instead of the disk end.
- Whether C-SCAN counts the return jump varies by book — **state your convention** in the answer.

## 4. Files and directories

A **file** is a named collection of related information on secondary storage. Attributes: name, identifier, type, location, size, protection, timestamps, owner. Operations: create, open, read, write, seek (reposition), delete, truncate, close. The OS keeps an **open-file table**.

**Access methods:** **sequential** (in order — tapes, logs), **direct/random** (any block by number — databases), **indexed** (an index points to blocks — ISAM).

**Directory structures:**
- **Single-level** — one directory for all; name clashes.
- **Two-level** — a directory per user.
- **Tree-structured** — subdirectories; absolute and relative paths.
- **Acyclic graph** — sharing via links (hard and symbolic).
- **General graph** — cycles possible; needs garbage collection.

## 5. Allocation methods

| Method | How | Plus | Minus |
| --- | --- | --- | --- |
| **Contiguous** | each file occupies consecutive blocks (start, length) | fast sequential **and** direct access | **external fragmentation**; files hard to grow |
| **Linked** | each block points to the next (start, end) | no external fragmentation; files grow easily | **sequential access only**; pointer space; one broken pointer loses the rest. **FAT** (file allocation table) keeps the links in a table → direct access possible |
| **Indexed** | an **index block** lists all the file's blocks | direct access, no external fragmentation | index-block overhead; large files need linked, multilevel or **combined** schemes |

**UNIX inode** (combined scheme): 12 **direct** pointers + **single**, **double** and **triple indirect** pointers. With 4 KB blocks and 4-byte pointers (1024 pointers per block), max file ≈ 48 KB + 4 MB + 4 GB + 4 TB.

**Free-space management:** **bit vector** (bitmap — 1 bit per block; easy to find contiguous runs), **linked list** of free blocks, **grouping**, **counting** (start, length runs).

**File-system performance:** buffer cache / page cache, **read-ahead** and **free-behind** for sequential access, keeping metadata and data close, **journaling** (log metadata changes for fast, consistent crash recovery — ext4, NTFS), defragmentation for HDDs.

## 6. I/O techniques

**Programmed I/O** (polling), **interrupt-driven I/O**, **DMA** (see [Organisation lesson 7](/learning-guide/nec/organization/07-io-multiprocessors/)). Kernel I/O subsystem: **buffering** (cope with speed mismatch), **caching**, **spooling** (queue output for a device that can't interleave — printers), device reservation, error handling. Device drivers hide hardware detail behind a uniform interface; device types: block, character, network.

## 7. Protection, security and administration

- **Protection** (internal — controlling access): access matrix, **access control lists** (per object), **capability lists** (per subject); UNIX permissions **rwx** for owner/group/others — `chmod 754 file` → owner rwx, group r-x, others r--. Principle of **least privilege**.
- **Security** (external threats): authentication (passwords — stored salted and hashed; two-factor), malware (viruses, worms, Trojans, trap doors, logic bombs), buffer overflows, denial of service. **Trusted systems** and the **reference monitor** (every access checked); the **trusted computing base**; security classes (Orange Book).
- **User accounts:** administrator/root (full control), standard users, guest; groups; `useradd`, `passwd`, `usermod` on Linux; a standard user needs the administrator password to change system settings.
- **Startup (boot):** power on → **BIOS/UEFI** runs **POST** (power-on self-test) → finds the boot device → **bootloader** (GRUB, Windows Boot Manager) from the MBR/EFI partition → loads the **kernel** into memory → kernel initialises hardware and mounts the root file system → starts the first process (**init / systemd**) → services and login.
- **Shutdown:** notify processes, stop services in order, flush buffers and caches to disk, unmount file systems, then halt or power off — an unclean shutdown risks file-system inconsistency (fixed by `fsck`/`chkdsk` or journaling).

## Lok Sewa: write it (5 marks · 8 minutes)

**Question.** Explain the SCAN and C-SCAN disk-scheduling algorithms. For requests 98, 183, 37, 122, 14, 124, 65, 67 with the head at 53 (cylinders 0–199) moving towards 199, find the total head movement for each.

<details>
<summary>Model answer</summary>

**SCAN (elevator).** The head moves in one direction serving every request until it reaches the end of the disk, then reverses and serves requests in the opposite direction. Waiting times are more uniform than SSTF and there is no starvation, but cylinders just visited wait longest.

Towards 199: 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 → 37 → 14. Movement = (199 − 53) + (199 − 14) = 146 + 185 = **331 cylinders**.

**C-SCAN (circular SCAN).** The head serves requests in one direction only; on reaching the end it returns immediately to the other end without serving, then continues in the same direction. It treats the cylinders as a circular list, giving more uniform waiting times.

Towards 199: 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 → (jump) 0 → 14 → 37. Movement = 146 + 199 + 37 = **382 cylinders** (counting the return sweep; 183 if the return is not counted).
