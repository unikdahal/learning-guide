## 1. Basics

- **Logical (virtual) address** — generated by the CPU; **physical address** — seen by memory. The **MMU** translates at run time.
- **Address binding** at compile time (absolute code), load time (relocatable code) or **execution time** (needs hardware; allows moving processes).
- **Base (relocation) and limit registers** give simple protection: every address must be < limit; physical = base + logical.
- **Swapping:** move a whole process to disk (backing store) and back, to fit more processes.
- **Dynamic loading** (load a routine when first called) and **dynamic linking** (shared libraries, DLLs) save memory.

## 2. Contiguous allocation and fragmentation

Each process gets one contiguous block.
- **Fixed partitions** → **internal fragmentation** (wasted space **inside** an allocated partition).
- **Variable partitions** → **external fragmentation** (enough total free memory, but in pieces too small to use).
- Placement: **first fit** (first hole big enough — fast), **best fit** (smallest adequate hole — leaves tiny unusable holes), **worst fit** (largest hole).
- **Compaction** shuffles processes to merge holes (needs run-time relocation; expensive).

Example — holes of 100, 500, 200, 300, 600 KB; requests 212, 417, 112, 426 KB:
- **First fit:** 212 → 500 (leaves 288), 417 → 600 (183), 112 → 288, 426 → **must wait**.
- **Best fit:** 212 → 300, 417 → 500, 112 → 200, 426 → 600 → **all fit**.
- **Worst fit:** 212 → 600 (388), 417 → 500, 112 → 388, 426 → **must wait**.

**Free-space management:** bitmaps (one bit per block), linked lists of holes, **buddy system** (blocks of powers of 2 split and merged with their "buddy").

## 3. Paging

Split **physical memory into frames** and **logical memory into pages** of the same size (a power of 2, e.g. 4 KB). Any page can go in any frame → **no external fragmentation** (only internal, in the last page — half a page per process on average).

**Logical address = page number p + offset d.** With page size 2ⁿ, the offset is the low n bits.
**Physical address = frame number (from the page table) × page size + d.**

**Worked.** Page size 1 KB (1024 B). Logical address **2500** → p = ⌊2500 / 1024⌋ = **2**, d = 2500 − 2048 = **452**. If page 2 is in frame **5**: physical = 5 × 1024 + 452 = **5572**.

**Sizing.** 32-bit logical addresses, 4 KB pages → offset 12 bits, page number 20 bits → **2²⁰ pages**; with 4-byte entries the page table is **4 MB** per process — hence:
- **Multilevel (hierarchical) page tables** — page the page table (two-level: 10 + 10 + 12 bits).
- **Hashed page tables** and **inverted page tables** (one entry per **frame**, not per page — small, but slow to search).

**Page-table entry** bits: frame number, **valid/invalid** (present), protection (read/write/execute), **dirty (modified)**, **referenced**.

### TLB — translation lookaside buffer

The page table lives in memory, so every access would need **two** memory accesses. The **TLB** is a small, fast associative cache of recent translations.

**Effective access time (EAT)** with TLB time t, memory time m, hit ratio h:
**EAT = h·(t + m) + (1 − h)·(t + 2m)**

Example: t = 20 ns, m = 100 ns, h = 0.8 → 0.8 × 120 + 0.2 × 220 = 96 + 44 = **140 ns** (vs 200 ns with no TLB). With h = 0.98 → 0.98 × 120 + 0.02 × 220 = **122 ns**. (Some books ignore t; read the question.)

**Shared pages:** reentrant (read-only) code can be mapped into many processes' page tables once — shared libraries.

## 4. Segmentation

Memory as the programmer sees it: variable-size logical **segments** — code, data, stack, heap, a function. Logical address = **(segment number, offset)**; the **segment table** holds base and limit for each.

Example: segment 2 has base 4300, limit 400. Address (2, 53) → 4300 + 53 = **4353**. Address (2, 500) → 500 ≥ 400 → **trap (segmentation fault)**.

| Paging | Segmentation |
| --- | --- |
| fixed-size pages, invisible to the programmer | variable-size segments, a logical unit visible to the programmer |
| no external fragmentation; internal in the last page | external fragmentation; no internal |
| address = page number + offset (one address space) | address = (segment, offset) (two-dimensional) |
| page table: frame per page | segment table: base and limit per segment |
| sharing and protection per page | natural sharing and protection per logical unit |

**Segmentation with paging** (each segment is paged) combines both — the x86 design.

## 5. Virtual memory and demand paging

**Virtual memory** separates logical memory from physical memory so that a program can be **larger than RAM**, more programs fit at once, and less I/O is needed to load and swap. Implemented by **demand paging**: load a page only when it is first referenced (a **lazy swapper / pager**).

**Page fault** — a reference to a page whose valid bit is invalid (the page is **not in main memory**):
1. The MMU traps to the OS.
2. The OS checks the reference is legal (otherwise kill the process).
3. Find a free frame (or choose a **victim** with page replacement; write it out if **dirty**).
4. Read the page from disk into the frame.
5. Update the page table (valid bit, frame number).
6. **Restart the instruction** that faulted.

**EAT with page faults:** EAT = (1 − p)·m + p·(fault service time). With m = 200 ns, service 8 ms and p = 1/1000 → 0.999 × 200 + 0.001 × 8,000,000 ≈ **8.2 µs** — **40 times slower**. To stay within 10% of 200 ns, p must be below about 1 in 400,000. Page faults must be rare.

**Copy-on-write:** after `fork()`, parent and child share pages until one writes, then that page is copied.

## 6. Page replacement

When memory is full, choose a victim page. Try the textbook reference string:

<PageLab />

Reference string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1 with **3 frames**:

| Algorithm | Rule | Faults |
| --- | --- | --- |
| **FIFO** | evict the page loaded earliest | **15** |
| **Optimal** (OPT, MIN) | evict the page used furthest in the future | **9** (the minimum possible) |
| **LRU** | evict the page unused for longest | **12** |

**Belady's anomaly:** with FIFO, **more frames can cause more faults**. String 1 2 3 4 1 2 5 1 2 3 4 5: **3 frames → 9 faults, 4 frames → 10**. LRU and optimal are **stack algorithms** and never show it.

**LRU approximations** (exact LRU needs hardware support): reference bit, **second-chance (clock)** algorithm, enhanced second chance (reference + dirty bits), LFU/MFU counting.

## 7. Frame allocation and thrashing

- **Allocation:** equal or **proportional** (to process size); global replacement (take frames from anyone) vs local (only your own).
- **Thrashing:** a process lacks frames for its active pages, so it faults constantly and spends more time paging than executing; CPU utilisation collapses, the OS adds more processes, making it worse.
- Fixes: **working-set model** (keep each process's set of pages used in the last Δ references in memory; suspend a process if the total demand exceeds the frames), **page-fault-frequency** control (give frames when the fault rate is too high, take them when too low), add RAM, lower the degree of multiprogramming.

## Lok Sewa: write it (10 marks · 16 minutes)

**Question.** What is virtual memory? Explain demand paging and the steps in handling a page fault. Differentiate paging and segmentation.

<details>
<summary>Model answer</summary>

**Virtual memory** is a memory-management technique that separates the logical address space seen by a program from physical memory, so that only the parts of a program currently needed are in RAM and the rest stays on disk. Benefits: programs larger than physical memory, more processes in memory (higher multiprogramming and CPU utilisation), less I/O to load or swap, and easier sharing.

**Demand paging.** Pages are loaded into memory only when they are referenced. Each page-table entry has a valid–invalid bit; invalid means the page is not in memory (or not part of the address space).

**Handling a page fault.** *(Draw the six-step diagram: CPU → page table → trap → OS → disk → free frame → update table → restart.)*
1. A reference to a page marked invalid causes a trap to the OS.
2. The OS checks an internal table: an illegal reference terminates the process; a legal one means the page is on disk.
3. A free frame is found; if none, a victim is chosen by page replacement (written to disk if dirty).
4. A disk read brings the page into the frame.
5. The page table is updated (frame number, valid bit set).
6. The interrupted instruction is restarted.

**Paging vs segmentation.**

| Paging | Segmentation |
| --- | --- |
| Memory divided into fixed-size pages/frames | Memory divided into variable-size logical segments |
| Invisible to the programmer | Visible; matches program structure |
| Internal fragmentation | External fragmentation |
| Logical address: page number + offset | Logical address: segment number + offset |
| Page table maps pages to frames | Segment table holds base and limit |
| Simpler allocation; any free frame | Needs a hole large enough; compaction may be needed |
| Protection/sharing per page | Protection/sharing per logical unit |

</details>
