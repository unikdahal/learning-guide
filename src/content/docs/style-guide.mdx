Three hundred articles only feel like one guide if they share a visual language. This page is
the reference for writing them.

## Article structure

Every article follows the same shape, so readers always know where they are:

1. **The question.** One or two paragraphs on the problem this article solves, in plain words.
2. **The idea.** The core mechanism, explained from first principles, with a figure.
3. **Worked example.** Concrete data, step by step, usually with a stepper.
4. **In real engines.** How DataFusion, Spark, DuckDB and others actually do it, with links to source.
5. **Costs and trade-offs.** When it wins, when it loses, and what the numbers depend on.
6. **In Rust.** A small, runnable implementation or a pointer to the lab.
7. **Check yourself.** Three to five questions, then further reading.

Claims about performance state what was measured and on what. Hypotheses are labelled as such.

## Pipeline colors

Diagrams color record batches and edges by pipeline, using the same three colors everywhere.
Blue is a build or upstream pipeline, teal is the main probe pipeline, violet is final output.
Amber is reserved for spilling, warnings and failure.

## Code

Rust is the language for all examples. Keep snippets short and runnable, and link the full
version in the lab repository.

```rust title="filter.rs"
use arrow::array::{BooleanArray, Int64Array};
use arrow::compute::kernels::cmp::gt;

/// Vectorized predicate: one kernel call evaluates the whole batch.
fn amount_over(amounts: &Int64Array, threshold: i64) -> BooleanArray {
    gt(amounts, &Int64Array::new_scalar(threshold)).expect("same length")
}
```

## Interactive visuals

When a visual needs real interaction, such as a zone-map explorer or a hash table you insert
into, write it as an Astro component in `src/components/visuals/` and import it into the
article. Follow these rules:

- Draw SVG at roughly 1:1 with the text column: a viewBox about 640 units wide keeps 13px labels at 13px.
- Use theme tokens (`--sl-color-*`, `--qe-pipe-*`), never hard-coded colors, so dark and light both work.
- Respect `prefers-reduced-motion` and provide a pause control for anything that loops.
- Give every SVG a role and an accessible label that states what it shows.
- Make it work at phone width.
